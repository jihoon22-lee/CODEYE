# 문서 계약 후속 검토

수락된 문서가 약속한 사용자 동작과 미확인 판정 한 건을 읽는다. 같은 적용 범위에서 입력 조건이 실제 구현의 분기·호출을 거쳐 어떤 결과가 되는지 확인한다. 원문에 있는 조건과 결과의 의미를 유지한다. 기존 이유는 새 근거가 답해야 할 질문으로 사용한다.

- 일치(`match`)는 문서 조건에서 도달하는 실행 경로와 사용자에게 돌아가는 결과를 읽을 수 있을 때 사용한다. 보조 함수나 값의 정의만 보이면 공개 진입점이나 호출부가 이어지는지 확인한다.
- 부분 일치(`partial`)는 서로 다른 적용 조건에서 실제로 지켜지는 결과와 실제로 어긋나는 결과를 각각 확인했을 때 쓴다. 두 조건과 결과를 구분해 구현 근거를 하나씩 인용한다. 일부만 확인했고 다른 부분의 준수 여부를 모르면 전체 계약은 미확인이다.
- 불일치(`mismatch`)는 문서 조건에서 도달하는 실제 구현이 다른 결과를 내는 분기나 반환 값을 읽을 수 있을 때 사용한다. 범위 밖 입력, 도달하지 않는 반례나 문서가 언급하지 않은 동작은 그 계약의 반례가 아니다.
- 정의·선언·주석·문자열의 단어만 같거나 호출 경로·결정 분기·반환 값을 확인할 수 없으면 미확인(`unknown`)을 유지한다. 새 구현에서 확인한 부분이 있으면 해당 근거와 여전히 확인할 조건을 함께 적는다. 관련 계약이 서로 충돌하거나 구현 발췌가 서로 다른 적용 조건을 보여 올바른 경로를 선택할 수 없을 때도 미확인이다.

코드와 함께 제시된 테스트 본문에서 그 조건의 입력과 기대 결과를 검사하는 단언이 보이면 해당 근거를 함께 인용한다. 테스트 본문은 정적으로 읽은 소스이며 실행 결과는 제공되지 않는다. 주석과 선언, 테스트만으로는 실제 사용자 동작을 확정할 수 없다. 다른 계약이나 발견을 추가하지 않는다.
