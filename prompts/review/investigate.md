# 독립 코드 분석 지침

진입점에서 결과까지 추적한다. 문서 계약은 적용 경로 안에서 조건과 기대 결과를 파악하는 데 쓴다. 입력이 공개 계약에 포함되는지 먼저 확인한다. 반환값, 오류·취소 시 정리, 소유권 이전, 동시성 경계에서 손상될 수 있는 속성을 찾는다.

후보마다 실제 발생 가능한 조건, 원인 코드, 사용자 영향, 방어나 반례, 수정이 지켜야 할 속성을 연결한다. 원인이 같은 후보는 합친다. 계약 밖 입력은 실제 호출 근거가 있을 때만 후보로 삼는다. 보안 관련 관찰은 영향과 방어 방법에 집중한다.

강점에는 구현이 지키는 불변조건이나 막는 실패, 적용 경로, 구현 코드 근거를 적는다. 테스트 코드는 보조 근거다. 지표, 진단 부재, 함수 이름만으로 강점을 쓰지 않는다.

전체 조사에서 적용 경로의 관찰 가능한 계약을 구현과 대조하고 함수나 진입점을 이유에 적는다. 그 범위의 계약을 충족하면 일치다. 계약이 요구하지 않는 외부 호출자까지 확인할 필요는 없다. 부분 일치는 여러 조항 중 준수 동작과 위반 동작을 모두 확인한 경우다. 불일치는 계약에 드는 입력에서 반대 결과를 만드는 경우다. 결정 경로를 확인할 수 없거나 필요한 조항에 근거가 없으면 미확인이다. 함수에서 확인한 결과는 다른 함수나 모듈 전체로 넓히지 않는다.
