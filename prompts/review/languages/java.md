# Java 검토 팩

## 먼저 확인

JDK와 `--release`, 소스 세트, Maven·Gradle 모듈, 컴파일 classpath와 테스트 런타임을 확인한다. 선언상 사용해야 하는 버전과 분석 도구가 실제로 관측한 버전을 구분한다. 생성 소스와 annotation processor가 추가하는 동작은 근거가 있는 경우에만 사용한다.

## 핵심 검토

- 호출 계약: import·수신자 타입·인자 타입으로 실제 선언을 확인한다. overload 선택과 override에 따른 런타임 구현을 구분하고, 상위 인터페이스 선언과 구현 클래스의 입력·반환·예외 조건을 비교한다.
- 오류와 자원: checked·unchecked 예외의 변환과 복구, try-with-resources의 종료 순서, 트랜잭션 commit·rollback, 부분 쓰기와 예외를 억제한 실패 경로를 확인한다.
- 데이터: `null`·빈 컬렉션·`Optional`의 계약, `equals`와 `hashCode`, 컬렉션 변경과 방어적 복사, 고정소수 연산의 자릿수와 반올림을 대조한다.
- 비동기와 공유 상태: executor 소유권과 종료, `CompletableFuture`의 실패·취소 전달, 동기화 경계와 공유 객체의 상태 변경을 읽는다.
- 테스트: JUnit 등에서 실제로 호출한 구현, mock이 바꾼 경계, 입력과 단언을 확인한다. parameterized test의 원문과 각 케이스의 실행 결과를 따로 읽는다.

## 반증

호출자의 입력 검증, 상위 예외 처리와 자원 정리, 타입으로 배제되는 상태, overload의 더 구체적인 구현을 확인한다. 프록시·리플렉션·프레임워크 주입이 결정하는 대상은 확인된 설정이나 코드가 있을 때 연결한다.

## 제출

호출부와 선택한 선언, 결과를 바꾸는 분기, 관련 테스트 원문의 위치를 연결한다. 확인하지 못한 classpath·런타임 수신자·빌드 조건은 남은 가정으로 기록한다. 테스트의 실행이나 재현은 실제 실행 기록이 있을 때만 보고한다.
