# 01. 기능·비기능 요구사항

MUST는 필수다. SHOULD는 근거를 기록하고 조정할 수 있다. ID는 구현 작업·테스트·설계 변경에서 유지한다.

## 2. 분석 프로필

`deep-review`가 기본이다. 문서·환경 진단, 설치된 상호 보완적 정적 검사, 주요 경로 검토, 후보 반증, 보고서를 포함한다. `with-tests`는 승인된 빌드·기존 테스트를 추가한다. `focused`는 특정 모듈·관심 영역·PR 중심이며 영향받는 다른 파일을 읽을 수 있다.

프로필은 범위·예산을 정하며 실행 권한을 높이지 않는다. 기본 프로필이 lint 한 번과 LLM 요약만 실행하면 요구 미충족이다. 프로젝트별 환경 부족은 보고하고, 결과를 볼 수 있는 나머지 검사는 계속한다.

## 3. 사용자 역할

운영자는 노드·풀·모델·도구·공통 정책을 관리한다. 프로젝트 관리자는 소스·멤버·예약·분석 설정을 관리한다. 실행자는 분석·취소·보고서 검토, 열람자는 읽기만 가능하다. 개인 모드에서도 owner ID와 프로젝트 ACL은 존재한다. 서버 실행 계정의 NFS 권한이 모든 웹 사용자에게 자동 승계되지 않는다.

## 4. 비기능 요구

| ID | 요구 |
|---|---|
| NFR-001 | Windows 11과 RHEL 8.10 Native 우선 검증. macOS는 초기 필수 보증 범위 아님 |
| NFR-002 | 실행 API는 영속 큐 등록 후 202. 분석 완료를 기다리지 않음 |
| NFR-003 | 관리 서버 재시작 뒤 실행·증거·보고서 복구, 노드 미전송 이벤트 재전송 |
| NFR-004 | 정상 연결 시 상태 표시 지연 5초 이내를 검증 목표로 삼음. 미측정 목표임 |
| NFR-005 | 키보드·검색·필터·색상 외 상태 구분·대형 목록 페이지 처리 |
| NFR-006 | TLS, 토큰 분리, 민감값 마스킹, 감사 로그. loopback 개인 모드 예외 명시 |
| NFR-007 | 산출물 hash·크기 검증 후 게시. 미완료 업로드 노출 금지 |
| NFR-008 | 모델 응답 오류는 제한된 복구 후 부분 완료. 무검증 내용 게시 금지 |
| NFR-009 | 한 도구의 실패/OOM이 관리 서버와 다른 작업을 종료시키지 않게 배치·제어 |
| NFR-010 | 자원·호출량·비용 추적. 호출 수 증가를 정확도 향상으로 해석하지 않음 |

## 5. 해석

최신 커밋은 소스 확보 시 관찰한 HEAD다. 같은 run의 재시도는 확정 입력을 유지한다. 원본 미변경과 운영 자격증명 미사용을 보장하도록 설계하지만 동일 호스트·NFS의 자원 영향이 0이라고 표현하지 않는다. Native는 작업공간 분리와 프로세스 제어를 제공하며 OS 샌드박스와 같지 않다.
