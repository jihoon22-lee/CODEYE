# W14 R0 회귀 시험과 개인 프로젝트 파일럿

한국 시간 2026년 11월 18일, Linux의 실제 PostgreSQL 컨트롤러와 별도 신원의 에이전트 두 대를 한 WSL2 호스트에서 실행했다. 합성 Go 입력 20개와 공개 CODEYE의 고정 사본 1개에서 Go vet, 맥락 파악, 독립 후보 조사, 반증 검토, 보고서 게시·조회 경로를 통과했다. 공개 HTTPS Git 입력도 별도로 실행했다.

## 입력과 결과

| 입력 | 모델 검토 | 결과 |
|---|---|---|
| 개발용 결함·수정 5쌍 | 수행 10/10 | 원래 결함 5/5 포착, 수정 후 같은 결함 재지적 0/5 |
| 보류 결함·수정 5쌍 | 수행 10/10 | 원래 결함 5/5 포착, 수정 후 같은 결함 재지적 0/5 |
| 공개 CODEYE `bcfad99d68b363f083801d75b3deab613c0fa321`의 로컬 사본 | 수행 | 목록 179개, 도구 처리 59개, 모델에 제공한 파일 8개. Go vet 진단 0건, 모델 후보 1건 |
| 공개 Git `main` | 소스 정책에 따라 미수행 | 실제 획득 SHA `f50dc6eafb87a41a55b3442ec8f6849174d5146b`, Go vet 성공, 필수 모델 작업 3개 정책 제외, 보고서 `partial` |

Go 1.27.4와 OpenCode 1.19.5, 명시적으로 설정한 GPT-6.2 Sol을 사용했다. 워커 2개가 동작할 수 있도록 로컬 노드 두 개를 등록하고 풀의 최소·최대를 0과 2로 설정했다. Go 도구는 설치된 로컬 모듈 캐시를 사용했다. 합성 사례와 공개 파일럿 원본의 트리 해시를 전후에 대조했다. 22개 보고서가 모두 게시되기까지 약 363초가 걸렸다. 대기열 시간이 포함되며 DB 생성·제품 빌드 시간은 제외했다.

R0의 연결 시험과 재확인을 모두 포함한 비용 장부에서 호출 83건이 정산됐다. 이 중 82건은 정상 응답, 1건은 HTTP 오류였다. 별도 최초 연결 시험을 더하면 보고된 사용량 기준 추정은 약 0.99달러, 실패 예약을 포함한 보수적 장부 차감은 약 2.20달러였다. 정산 대기 0건을 확인한 뒤 relay를 종료했다. 공급자 청구서는 확인하지 않았다.

## 합성 표본의 해석

모든 함수에 짧은 공개 계약 주석이 있다. 다섯 쌍에는 같은 계약을 담은 README도 제공했다. 실행 입력에는 평가 라벨·전후 구분·확인용 테스트가 들어가지 않는다. 원인 종류를 기준으로 개발·보류 집합을 나눴다. 각 원래 구현은 별도 계약 시험에서 실패했고 수정 구현은 통과했다. 발생 조건과 잘못된 결과가 모두 맞아야 탐지로 집계했다.

| 사례 | 수정 전 확인한 원인 | 수정 후 별도 보고와 검토 결과 |
|---|---|---|
| Q01 | 마지막 표본 누락 | 정수 범위를 넘는 합. 표현 범위 정보 |
| Q02 | 여유 용량을 공유한 배열 덮어쓰기 | 별도 발견 없음 |
| Q03 | UTF-8 첫 문자 절단 | 잘못된 UTF-8 입력의 처리 규칙이 모호함. 계약 정보 |
| Q04 | 값 0을 키 부재로 처리 | 별도 발견 없음 |
| Q05 | 호출자에게 넘길 reader를 반환 전에 닫음 | nil reader를 성공으로 반환. 열린 reader라는 성공 조건을 별도로 위반 |
| Q06 | 원인 오류 체인 단절 | nil 원인을 넘길 때의 기대 동작이 불명확함. 모델도 판단 보류 |
| Q07 | 초 단위를 나노초로 취급 | 64비트에서 큰 초 값의 변환 오버플로. 표현 범위 정보 |
| Q08 | 전부 음수인 입력에서 최댓값 0 반환 | 빈 입력의 패닉. 계약이 비어 있지 않은 입력을 명시함 |
| Q09 | 빈 이름도 반환 개수 제한에 포함 | 별도 발견 없음 |
| Q10 | 실수 변환 전에 정수 나눗셈 | 분모 0의 결과. 계약이 양의 분모를 명시함 |

합성 20건에서 Go vet 진단은 0건이었다. 모델이 제시한 발견 17건 중 16건은 제품에서 근거 있음, 1건은 판단 보류로 집계됐다. 수정본 10개 중 7개에 다른 경고가 나왔고, 그중 6개가 조치 검토 수에 들어갔다. 별도 정적 대조에서는 독립적인 계약 위반 1개, 정보성 3개, 요구 근거 부족 1개, 명시된 전제 밖 2개로 판정했다. 빈 입력·분모 0처럼 코드 동작이 맞아도 정상 사용의 결함으로 읽히는 항목이 있어 조치 우선순위가 과장될 수 있다. Q01 수정본은 사전 연결 시험에서는 경고 0건, 본 실행에서는 1건이었다.

합성 표본에서 맥락·조사 호출은 각각 20회였고 검증 호출은 17회였다. 조사 후보가 없는 3건은 검증 작업이 호출 없이 종료됐다. 절차를 나누어 정답과 코드를 대조한 개발 에이전트의 판정이다. 사람 검토자의 precision, 독자 사용성, 다른 프로젝트·언어의 탐지율은 측정하지 않았다.

## 실제 프로젝트에서 본 후보

고정 사본의 모델은 CLI가 출력 쓰기 오류를 무시하고 종료 코드 0을 반환할 수 있다는 후보를 냈다. 근거 위치는 `cmd/codeye/main.go`와 테스트다. 별도 QA에서 공개 커밋을 빌드한 후 Linux의 `/dev/full`에 표준 출력을 연결했다. 도움말과 임시 PostgreSQL에 대한 migrate가 모두 코드 0으로 끝났다. 후자의 경우 DB 테이블 생성은 성공했다. 보고서의 원래 판정은 코드 근거를 가진 `supported`다. 실제 운영 장애나 데이터 손실 여부는 확인하지 않았다.

사전 파일럿에서는 같은 공개 커밋에서 종료 직전의 신호 구독 정리가 후보로 나왔다. 두 실행이 서로 다른 후보를 낸 점과 179개 파일 중 모델에 제공한 파일 수를 함께 해석해야 한다.

## 확인 방법과 범위

- `python3 fixtures/r0-quality/corpus.py --check`로 모델 없이 결함 전후 10쌍의 계약 시험을 실행한다.
- `python3 scripts/test_postgres.py --web --nodes --scheduler`는 임시 Native DB, 제품 Go 워커, Chromium, 자동 증감·취소·회복을 시험한다.
- 실제 모델 파일럿은 Go, PostgreSQL 도구, 잠금 파일대로 설치한 웹 의존성, Chromium, 고정 OpenCode와 승인된 relay가 필요하다. `CODEYE_R0_RELAY_FILE`에 기존 relay descriptor를, `CODEYE_R0_RESULTS`에 새 비공개 결과 디렉터리를 지정하고 `python3 scripts/test_postgres.py --r0-pilot`을 실행한다. 이 시험은 실제 모델 요청을 보낸다. 기본 입력은 위 합성 쌍, 고정 공개 커밋, 공개 CODEYE의 HTTPS main이다. `CODEYE_R0_CASES`를 사용하면 `Q01-before,pilot`처럼 대상을 한정할 수 있다.
- `python3 scripts/r0_pilot.py --audit-results "$CODEYE_R0_RESULTS"`는 보관된 결과와 원본을 다시 대조한다. Git 시험에 기록된 commit 객체가 로컬에 있어야 한다. 본 실행의 보고서 22개에서 구조·통계·스냅샷과 주장 38개·근거 27개의 참조를 검사했다. 파일 위치·줄 범위·blob SHA가 일치했다. 이 검사는 주장 자체가 옳다는 보증과 구분한다.
- 본 실행에서 처음 페이지 밖의 프로젝트를 열지 못하던 브라우저 시험을 수정했다. 21개 후속 프로젝트를 만든 뒤 더 보기를 통해 이전 보고서를 찾아 API 수치와 3개 내보내기를 대조했다. 이어 최종 통합 후보에서 합성 결함 한 건, 공개 사본, Git을 다시 실행해 보고서 3건의 게시·조회와 Chromium 내보내기까지 통과했다.
- 두 에이전트는 같은 WSL2 머신에서 실행했다. Windows의 CI 범위는 Go 시험이다. RHEL 8.10 운영, Windows 실모델 파일럿, 다중 물리 노드 분할, 실제 독자 평가와 다섯 언어 비교는 미실행이다.

다음 W15는 프로젝트 문서·환경을 모듈별로 자동 탐색하는 작업이다. 첫 회귀 입력에는 문서 없는 모듈과 중첩 모듈, 서로 충돌하는 안내 문서를 함께 두고, 분석 계획에 선택된 자료와 제외 사유가 맞는지 확인한다.
