# 24. W03 최소 control API·인증·웹 호스팅

개인 모드 서버 시작, 일회용 로그인, 프로젝트 등록과 요청·취소 계약을 다룬다. 아래 W03 시험 기록은 당시의 API 범위다. 현재 지원되는 노드와 보고서 경로는 [통합 API](11-api-and-events.md)에서 확인한다.

## 1. 범위

- `internal/httpapi`: loopback 전용 HTTP API(`/api/v1`)와 같은 origin의 정적 웹 호스팅.
- `internal/domain/source.go`: source 선언(local/git)과 run 요청의 엄격한 decode·형식 검증.
- `internal/storage/postgres`: 세션·launch token·source root·provider 저장, 선언된 프로젝트 등록, 프로젝트 목록·요약, run 보기, 변경 여부를 알려 주는 취소, 읽기 전용 schema 상태.
- `migrations/sql/0002_auth_and_sources.sql`: 아래 §5 테이블. 0001은 수정하지 않았다.
- `cmd/codeye`: 사용자·source root·provider 관리, login link, `serve`.

`codeye start`는 W06 이후의 supervisor(controller+agent)로 남겨 두었다. W03의 `serve`는 controller만 실행한다. 등록된 노드가 없으면 run은 `queued`에 머물고 API는 `waiting_reason: execution_unavailable`을 표시한다.

## 2. 실행 순서

```bash
export CODEYE_DATABASE_URL=...            # 프로세스 환경으로만 전달
codeye migrate                            # 명시적 schema 적용(serve는 migrate하지 않음)
codeye user create --name "me"            # {"id":"..."}
codeye source-root add --label work --path /abs/dir
codeye source-root grant --root ROOT_ID --user USER_ID
codeye provider add --kind github --host github.com      # 선택
codeye serve --user USER_ID               # 기본 127.0.0.1:7331, web/dist, .codeye/login-link
```

`serve`는 listen 주소가 loopback IP가 아니면 거부한다. migration 이력이 이 binary의 최신과 정확히 일치하지 않으면(outdated/newer/inconsistent) `codeye migrate` 안내와 함께 종료한다. `--user`를 주면 일회용 login link를 `--login-link-file`(기본 `.codeye/login-link`)에 기록하고 파일 경로만 출력한다. 별도 프로세스에서는 `codeye login-link --user ID [--output P] [--origin http://127.0.0.1:7331]`을 쓴다. SIGINT/SIGTERM에서 최대 10초 graceful shutdown한다.

login link 파일은 같은 디렉터리의 임시 파일(0600)을 rename해 만든다. 대상 경로의 symlink를 따라가지 않고, 대상이 일반 파일이 아니면 거부한다. 상위 디렉터리는 0700으로 만든다. Windows에서는 POSIX mode가 ACL을 제한하지 않으므로 사용자 profile 등 보호된 위치를 지정해야 한다(Windows 시험 미실행).

## 3. 인증과 브라우저 보호

| 항목 | 계약 |
|---|---|
| 사용자 생성 | CLI(운영자)만. HTTP로 사용자를 만들지 않는다 |
| launch token | 32 byte 난수(base64url 43자), DB에는 SHA-256만 저장, 10분, 한 번만 교환. URL fragment(`#launch=`)로 전달해 HTTP 요청·서버 로그에 실리지 않는다 |
| 세션 | `POST /session`이 token을 소비하고 같은 트랜잭션에서 세션 생성. 잠금 순서는 user(FOR SHARE)→token→session으로 `DisableUser`(user FOR UPDATE→session 폐기)와 직렬화된다. cookie `codeye_session`(HttpOnly, SameSite=Strict, Path=/, 12시간 절대 만료, sliding 없음). 만료는 DB 시각 |
| CSRF | `X-CODEYE-CSRF` = base64url(SHA-256("codeye-csrf\0"+session token)). 서버만 계산할 수 있고 `/session` 응답으로 전달. `POST /session`을 제외한 상태 변경 요청에 필수 |
| Origin | 상태 변경 요청은 `Origin`이 `http://`+Host와 정확히 같아야 한다. `Sec-Fetch-Site`가 있으면 `same-origin`이어야 한다 |
| Host | `127.0.0.1:P`, `localhost:P`, `[::1]:P`만 허용(DNS rebinding 방어). 정적 파일 포함 모든 요청에 적용 |
| 폐기 | `DELETE /session`, `codeye user disable`(모든 세션 폐기, 이후 교환 거부) |
| 응답 header | CSP `default-src 'self'` 등, `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy: no-referrer`, API는 `Cache-Control: no-store`, 모든 응답에 `X-Request-ID` |

Secure cookie와 `__Host-` prefix는 평문 loopback에서 쓸 수 없어 사용하지 않는다. LAN 공개·TLS·Bearer 인증은 구현하지 않았고 serve가 허용하지 않는다.

## 4. API

아래 표는 [OpenAPI](../api/openapi.yaml) 중 W03에서 추가한 operation이다. 현재 R0에는 W06 노드와 W09 보고서 경로도 있다.

| Method / Path | 인증 | 결과 |
|---|---|---|
| GET /health | 없음 | `{status:"ok"}` |
| GET /ready | 없음 | 200 `{status:"ready",schema_version}` / 503 `{status:"not_ready",reason}`; reason = database_unavailable, schema_outdated, schema_newer, schema_inconsistent. 읽기 전용 |
| POST /session | Origin | `{launch_token}` → 201 `{user_id,csrf_token,expires_at}` + cookie; 잘못·사용·만료 → 401 |
| GET /session | 세션 | 같은 shape |
| DELETE /session | 세션+CSRF | 204, cookie 삭제 |
| GET /source-roots | 세션 | `{items:[{id,label}]}` 허가된 root만. 서버 경로 비노출 |
| GET /providers | 세션 | `{items:[{id,kind,host}]}` |
| POST /projects | 세션+CSRF | `{name?,source,description?,attachment_ids?}` → 201 Project + Location |
| GET /projects | 세션 | `?cursor&limit(1..100, 기본 20)` → `{items,next_cursor}` 최신순 keyset |
| GET /projects/{id} | 세션 | Project |
| POST /projects/{id}/runs | 세션+CSRF+Idempotency-Key | 202 `{id,status,version,url}` + Location |
| GET /runs/{id} | 세션 | RunView |
| POST /runs/{id}/cancel | 세션+CSRF | 변경했으면 202, 이미 종료·취소 중이면 200 (RunAck) |

Project는 `{id,name,source,revision,source_status:"declared_unverified",capability_gaps:["source_access_unverified","execution_unavailable","report_unavailable"],last_run:{id,status}|null}`다. 등록은 형식과 권한만 검사한다. local은 허가된 source root와 상대 경로(`.` 또는 절대·드라이브·역슬래시·`..`·빈 구간이 없는 경로), git은 승인된 provider와 `https://<provider host>/<owner>/<repo>[.git]`, check-ref-format 부분집합의 branch다. 서버는 등록 시 파일 시스템·네트워크에 접근하지 않는다(존재하지 않는 root 경로로 시험). 이름이 없으면 경로 마지막 구간, root label, 저장소 이름에서 정한다. 저장되는 revision 1 config는 `{"config_version":1,"source":...,"description"?}`다.

R0 실행 상세의 단계 값은 run 상태다. 종료 task 수는 성공·실패·제외를 포함하며 task가 등록되기 전에는 전체 수를 알 수 없다. 대기 사유는 배정 가능 조건에서, 품질 판정은 게시 보고서에서 구한다. [진행 응답과 후속 설계](11-api-and-events.md)

### 오류

envelope `{error:{code,message,retryable,request_id,details}}`. message는 고정 문구이며 SQL·DSN·경로·token을 넣지 않는다.

| 상태 | code |
|---|---|
| 400 | INVALID_REQUEST (JSON 형식, 알 수 없는 필드, 중복 key, Idempotency-Key 누락/형식, cursor) |
| 401 | UNAUTHENTICATED |
| 403 | FORBIDDEN(역할 부족), HOST_REJECTED, ORIGIN_REJECTED, CSRF_REJECTED |
| 404 | NOT_FOUND(없음·비구성원·허가 없는 root·없는 provider·UUID 아님을 구분하지 않음) |
| 405 / 409 | METHOD_NOT_ALLOWED / IDEMPOTENCY_CONFLICT, CONFLICT |
| 413 / 415 | PAYLOAD_TOO_LARGE(64 KiB) / UNSUPPORTED_MEDIA_TYPE |
| 422 | VALIDATION_FAILED, SOURCE_UNSUPPORTED(ssh/scp/git://), ATTACHMENTS_UNSUPPORTED |
| 500 / 503 | INTERNAL / UNAVAILABLE(retryable=true; DB 오류 후 202를 반환하지 않음) |

## 5. 데이터와 저장 계약 변경

0002: `users.display_name`, `users.disabled_at`(한 번 설정 후 변경 불가), `users.created_at`; `projects.created_at`; `auth_launch_tokens(token_sha256, user_id, created_at, expires_at, used_at)`; `auth_sessions(id, user_id, token_sha256 UNIQUE, created_at, expires_at, revoked_at)`; `source_roots(id, label UNIQUE, path, created_at)` 불변; `source_root_grants(source_root_id, user_id)`; `providers(id, kind github|ghes, host, api_url, created_at)` 불변, github는 host `github.com`만. token·session 행은 식별·만료가 불변이고 used_at/revoked_at은 한 번만 설정된다. 모든 FK는 RESTRICT다.

W02 저장 API 변경: 프로젝트 구성원이 아닌 actor는 `ErrForbidden` 대신 `ErrNotFound`를 받는다(존재 비노출). 구성원의 역할 부족은 계속 `ErrForbidden`이다. W02 시험 기대값 3개를 갱신했다. 추가 method: `CreateUserNamed`, `DisableUser`, `IssueLaunchToken`, `ExchangeLaunchToken`, `SessionByTokenHash`, `RevokeSession`, `AddSourceRoot`, `GrantSourceRoot`, `ListSourceRoots`, `AddProvider`, `ListProviders`, `RegisterProject`, `ListProjects`, `GetProjectSummary`, `GetRunView`, `CancelRun`, `SchemaStatus`, `Ping`, `NewFromPool`(시험용 pool 주입). `CreateUser`·`CreateProject`·`Cancel` 등 기존 method는 유지했다. `migrations.Inspect`는 이력을 읽기 전용으로 검사한다.

## 7. 운영 경계

- 프로젝트 등록은 소스 위치의 선언이다. 분석 요청 뒤 워커가 취득·고정한다. 노드 인증에는 별도 Bearer 자격증명을 사용한다.
- 개인 모드는 loopback이다. 다중 사용자 배포·비공개 Git 인증·감사 운영은 별도 검증이 필요하다.
- 세션 cookie가 loopback의 다른 포트 서비스와 공유될 수 있다(cookie는 port를 구분하지 않음). CSRF·Origin 검사가 상태 변경을 막지만 같은 PC의 신뢰하지 않는 로컬 웹 서비스가 있는 환경은 별도 운영 판단이 필요하다.
- source root 경로는 등록 시점의 디렉터리 존재만 CLI가 확인한다. 실제 경로 정규화·symlink/junction 경계는 W04 acquire가 검사한다.

## 8. 롤백

0002는 forward migration이다. 개발 환경은 임시 schema/DB를 제거해 복원한다. 운영 DB에 적용한 뒤에는 0002를 수정하지 않고 다음 번호로 변경한다. 코드 롤백만 하면 이전 binary가 `schema_newer`로 멈추므로 backup 복구 또는 forward 수정이 필요하다.


## 9. 웹 개발과 브라우저 시험

`npm --prefix web ci` 후 `npm --prefix web test`, `npm --prefix web run build`를 실행한다. doctor validator는 pretest/prebuild에서 공통 Schema로부터 생성하며 브라우저에서 eval/new Function을 사용하지 않는다. 외부 CDN은 없다. 별도 Vite 개발 서버는 API와 동일 origin이 아니므로 인증 화면이 연결 불가를 표시하는 것이 정상이다. 실제 사용은 build한 web/dist를 codeye serve로 제공한다.

브라우저 시험은 개발용 Chromium이 필요하다. web 디렉터리에서 `npx playwright install chromium`을 명시적으로 실행한 뒤 Native PostgreSQL 도구를 PATH에 놓고 저장소 루트에서 `python3 scripts/test_postgres.py --web`를 실행한다. 임시 DB·사용자·source root·서버를 만들고 시험 뒤 모두 정리한다. 토큰·DSN은 trace/screenshot·저장소에 기록하지 않는다. CI의 브라우저 다운로드는 개발 시험 준비이며 제품 실행 시 외부 다운로드가 아니다.
