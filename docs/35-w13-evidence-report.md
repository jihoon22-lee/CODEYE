# W13 근거 보고서와 상세 화면

실행 상세에서 **보고서 열기**를 선택하면 게시된 리비전의 진단·발견·미확정·반증 수와 분석 한계를 볼 수 있다. 영역을 고른 뒤 개별 후보를 펼치면 발생 조건, 심각도를 판단한 이유, 영향, 개선 방향, 확인 방법이 나온다. 주장 옆의 근거를 선택하면 같은 발견 안에서 스냅샷 파일과 줄 범위 또는 도구 산출물로 이동한다. 모델이 본 파일 수를 계산할 수 없는 부분 실행은 미확인으로 표시한다.

## 집계와 출처

서버는 허가된 사용자의 보고서 요청에만 저장된 리비전을 돌려준다. 작업 키와 스냅샷 해시가 일치하는 검토 산출물을 읽고, 실제 선행 호출 기록과 후보 내용이 다음 단계와 일치하는지 확인한다. 후보 하나는 한 번만 집계한다. 검증 산출물이 없거나 선행 기록이 바뀌었을 때는 조사 단계의 후보를 미검증 상태로 남긴다. 일부 후보만 격리한 실패 산출물에는 근거를 확인한 다른 후보의 판정도 남을 수 있다. 전체 실행과 모델 검토의 완료 상태는 별도로 계산한다.

모델 검토 기록이 있는 리비전은 선택적 배열 `coverage.review_calls`에 역할·모델·OpenCode 버전·지침과 요청의 SHA-256·호출 결과를 제공한다. 각 호출은 실제 담당 역할에 한 번만 표시한다. 예를 들어 검토 호출 결과가 `accepted`여도 후보의 판정은 `refuted`일 수 있다. 수용한 응답의 내용으로 실제 실행이나 사람의 확인을 대신할 수 없다.

## 내보내기와 검증

화면에서 JSON, Markdown, HTML 링크는 현재 리비전을 가리킨다. 기본 내보내기는 코드 제외이며 자유 형식 문구·기호명·원시 진단을 가린다. 코드 포함을 선택하면 보관된 진단과 검토 문구, 위치를 볼 수 있다. 컨트롤러는 소스 전문을 보유하지 않는다.

- TC-90과 TC-91은 W12의 합성 반증 기록을 사용해 기각된 후보 하나, 반대 근거 ID, 깨진 호출 이력, 변경된 후보, 검증 실패·누락을 확인한다. 원시 도구 진단과 모델 후보는 각자의 출처로 표시한다.
- TC-92의 화면 시험은 스냅샷 범위, 검색, 조건과 증거 위치, 기본 내보내기, 다른 실행·잘못된 통계 거부를 확인한다. 실제 Chromium에서도 게시된 보고서의 발견 수를 API와 대조하고 세 가지 내보내기를 조회했다.
- Windows의 Go 시험과 프런트엔드 단위 시험은 자동 검증 대상이다. 실제 브라우저·모델 송수신 검증 환경은 Linux이며 RHEL과 다중 물리 머신의 동작은 미검증이다.
