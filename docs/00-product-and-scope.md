# 00. 제품 개요와 범위

상태: 설계 기준선 v0.1. 확정 요구는 사용자 결정이며, 설계 기본값은 이 문서 묶음이 제안한 구현안이다.

## 1. 제품 정의

CODEYE는 프로젝트에 맞는 분석 계획을 만들고, 독립 작업공간에서 정적 분석 도구와 LLM 검토를 수행하며, 개발자가 판단하고 수정할 수 있는 근거 중심 보고서를 제공한다. 핵심 가치는 경고 수가 아니라 분석의 깊이·유용성·설명의 정확성이다. 기존 CI 결과를 수집하는 대시보드가 아니다.

## 2. 확정 요구

| 범주 | 요구 |
|---|---|
| 우선 사용 | 개인 PC의 개인 프로젝트에서 검증한 후 부서원에게 공개 |
| 환경 | Windows 계열 개인 PC와 RHEL 8.10 폐쇄망을 우선 고려. 사내 패키지 미러·NFS·기존 툴체인 활용 |
| 배치 | 한 머신에서 시작하되 여러 머신에 에이전트를 등록해 확장 |
| 실행 | Native 기본. Docker·Podman은 선택. SSH 원격 작업 기능 없음 |
| 등록 | GitHub.com/GHES URL+브랜치 또는 서비스 계정이 읽을 수 있는 로컬 경로 |
| 맥락 | README·AGENTS·architecture·guide·docs와 환경 파일을 자동 탐색. 문서가 없어도 진행 |
| 추가 정보 | 사용자 설명·첨부·관심 영역은 선택. 필수 입력 부담을 늘리지 않음 |
| 소스 | 일반 실행은 확보 시 최신 브랜치 HEAD, PR은 대상 SHA, 로컬은 별도 복사본 |
| 트리거 | 수동, 시간대가 있는 예약, PR 이벤트, 권한이 있는 사용자의 댓글 명령 |
| 결과 | 실시간 상태, 단계·완료 수·추정 진행 정도, 요약·영역별·개별 상세 보고서 |
| 확장 | 운영자가 최소·최대 워커, 병렬 수와 자원 예산을 설정. 자동 증감 |
| 모델 | 사내에서는 허용된 OpenCode 연결을 우선. 직접 LLM API는 허용된 환경의 옵션 |
| 언어 | C/C++, Python, JavaScript/TypeScript, Go, Rust |

런타임·컴파일러 버전은 환경에서 탐지하고 프로젝트 요구와 대조한다. 문서에서 특정 최신 버전의 설치를 강제하지 않는다. 개인 PC의 정확한 OS·아키텍처·RAM은 구현 착수 시 확인한다.

## 3. 품질 축

**이해:** 요구사항을 발명하지 않고 문서 사실·코드 사실·추론을 구분한다. 함수 간 계약, 오류·취소 경로, 상태 전이, 동시성, 자원 수명, 구조적 성능 위험을 검토한다.

**다각도 검사:** 문법·규칙, 타입·컴파일 의미, 경로·데이터 흐름, 구조·복잡도, 비밀정보, 선택적 빌드·기존 테스트를 구분한다. 한 도구의 경고를 모델이 바꾸어 쓰는 것만으로 심층 분석을 주장하지 않는다.

**전달:** 문제→발생 조건→근거→영향→개선 방향→확인 방법을 연결한다. 미분석 영역은 보고서 첫 화면에서 알 수 있어야 한다.

## 4. 비목표

- 기존 CI/Coverity 연결, CI 결과 수집, CI 파일 생성, CI 결과에 따라 검사 생략.
- 초기 의존성 CVE 검사·패키지 업그레이드 권고. 의존성 선언은 환경 분석에 사용한다.
- 운영 인스턴스 DAST·부하 시험, 운영 DB 사용, 배포, 자동 수정 커밋.
- 모든 업무 요구사항 자동 복원, 모든 언어/OS/버전 지원, 무결함 인증.
- Native 환경에서 적대적 임의 코드를 안전하게 실행한다는 보안 샌드박스 보장.
- 초기 클라우드 VM 생성·삭제. 등록된 머신 안의 워커 증감과 별개다.

## 5. 제공 단계

| 단계 | 필수 결과 |
|---|---|
| R0 수직 검증 | Native, Git/local 입력, 한 언어 실도구+LLM+근거 보고서, 취소, 워커 자동 증감, 두 에이전트 계약 시험 |
| R1 개인 실용판 | 다섯 언어 탐색·핵심 어댑터, 예약·진행·비교, 지침 평가, OpenCode 실제 연동 |
| R2 부서 공개판 | 인증·권한 운영 검증, GHES App/PR/댓글, 다중 물리 노드 검증, 폐쇄망 배포 |
| 선택 확장 | Container 실행기, 고비용 분석기, 추가 인프라 용량 공급자 |

API 권한·프로젝트 소유권·노드 식별·lease는 R0부터 존재한다. R2에서 보안과 분산 상태를 뒤늦게 덧붙이지 않는다. R0 결과를 전체 제품 출시라고 표현하지 않는다.

## 6. 용어

프로젝트는 소스와 정책, run은 한 번의 분석 요청, attempt는 재시도를 구분하는 실행 실체, snapshot은 입력 기준점, task는 도구·LLM 작업이다. 노드는 머신, 에이전트는 상주 관리자, 워커는 한 번에 한 attempt를 맡는 프로세스다. finding은 여러 관찰과 근거를 묶은 논점이며 실제 결함 확정과 동의어가 아니다.
