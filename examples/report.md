# CODEYE 보고서 예시 — 임시 작업 디렉터리 정리

> **합성 예시.** 아래는 원하는 보고서 구조를 설명하기 위해 작성한 데이터다. 실제 CODEYE 분석기의 실행 결과나 사용자 프로젝트의 결함 발견 결과가 아니다. 기계 판독 원본은 [report.json](report.json)이다.

## 요약

| 항목 | 값 |
|---|---|
| 분석 대상 | 합성 함수 run_job, snapshot_cleanup_before |
| 실행 상태 | 완료 — 출력 계약상의 예시 상태 |
| 품질 판단 | 확인·개선할 사항 있음 |
| 발견 사항 | 1개, 소스 근거로 지지됨 |
| 재현 상태 | 이 보고서에서 실행 재현을 주장하지 않음 |
| 테스트 | 미실행으로 표시 |
| 분석 범위 | 함수 1개. 도구 처리량·모델 노출량은 미측정 |

**우선 조치:** 콜백이 실패할 때도 임시 디렉터리를 정리하도록 소유권과 예외 종료 경로를 확인한다. 정상 경로와 실패 경로를 각각 테스트한다.

## F-1. 콜백 예외가 발생하면 임시 디렉터리가 남을 수 있음

심각도 **Medium** · 검증 **Supported** · 처리 **Open**

### 발생 조건과 영향

콜백 `process`가 정상 반환 전에 예외를 발생시키고, 상위 호출자나 별도 서비스가 이 디렉터리를 정리하지 않는 경우다. 생성된 디렉터리의 삭제는 정상 반환 다음에만 있으므로 예외 경로에서 건너뛴다. 반복 실패 시 파일이 쌓일 수 있지만 실제 운영 영향과 디스크 소진 시점은 측정하지 않았다.

### 코드 근거

[확정 예시 소스의 run_job](../fixtures/cleanup/before.py), 9~13행:

```python
def run_job(root: Path, process: Callable[[Path], T]) -> T:
    workspace = Path(tempfile.mkdtemp(prefix="codeye-fixture-", dir=root))
    result = process(workspace)
    shutil.rmtree(workspace)
    return result
```

근거 ID는 `evidence_cleanup_code`다. JSON에는 파일 hash와 snapshot 기준 위치를 연결했다. 정리 함수가 존재한다는 사실만으로 예외 경로가 정리된다고 판단하지 않는다.

### 반증 검토와 남은 가정

함수 내부에는 finally나 context manager가 없다. 그러나 실제 프로젝트에서 외부 정리 서비스가 소유권을 갖는다면 영향이 달라질 수 있다. 이 예시는 외부 시스템이 없는 작은 합성 코드이며 실제 프로젝트의 소유권 계약을 대신하지 않는다.

### 개선 방향

이 함수가 디렉터리를 소유한다면 try/finally 또는 context manager로 정상·예외 경로 정리를 보장한다. [수정 예시](../fixtures/cleanup/after.py)는 기본 finally 구조를 보여준다. 실제 운영 코드는 정리 실패 시 원래 예외를 보존하는 정책까지 결정해야 한다.

### 확인 방법

정상 콜백과 예외 콜백을 각각 실행해 디렉터리 잔존 여부·반환값·예외 전달을 확인한다. [보조 테스트](../fixtures/cleanup/test_cleanup.py)는 이 합성 예제를 검사한다. 테스트가 통과해도 CODEYE가 자동으로 이 문제를 찾았다는 뜻은 아니다.

## 분석 공백

다른 파일·운영 환경·정리 서비스·실제 부하를 검토한 보고서가 아니다. 테스트 커버리지나 시스템 안전 점수를 제시하지 않는다. 의존성 CVE는 초기 제품 범위 밖이며 누락 검사로 감점하지 않는다.
